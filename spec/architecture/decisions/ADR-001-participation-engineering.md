# ADR-001 — Participation Engineering is a First-Class System

Status: ACCEPTED
Date: 2026-09-30

## Context
Execution may fail because an ecosystem actor is missing or not participating enough. Treating this only as routing would make the network passive.

## Decision
Create a first-class Participation Economics subsystem that can detect scarce useful behavior, form hypotheses, run controlled experiments, define incentive programs, fund rewards, attribute contributions, publish role-specific recognition and learn from outcomes.

Participation organizations are normal agent organizations. They have no financial authority.

## Constraints
- monetary rewards are protocol obligations;
- budgets are reserved before finalization;
- contribution attribution is evidence-backed and reproducible;
- program versions are immutable;
- anti-Sybil/collusion checks are required;
- leaderboards/points are projections;
- no incentive mechanism can override compliance, authorization, risk or security policy.

## Consequence
The system can actively grow liquidity, credit supply, borrower health, merchant acceptance, expert supply and ecosystem participation while preserving deterministic financial authority.
