# P2-W1-001 — Provider Connection Control Plane

Owner: Worker 1
Depends on: none

Implement the provider connection/authentication control plane, including vault-backed credential references, delegated authorization artifacts, isolated browser-session references, provider onboarding/activation state, ConnectedCapabilityInstance activation/deactivation, capability observations, credential/session rotation and reauthentication, provider activation records and safe operator controls. It must support both credential-bearing providers and local rails where PaySwap has no provider API credential.

Acceptance:
- no raw credential values or browser session material enter Git, agent context, logs or protocol events;
- supported auth modes are explicit: DELEGATED_OAUTH / CONNECTED_ACCOUNT / SCOPED_API_CREDENTIAL / INTERACTIVE_BROWSER_SESSION / PROVIDERLESS_RAIL;
- interactive browser login is performed by the account owner in an isolated secure browser runtime; the agent sees only an opaque session/authorization reference;
- browser sessions support expiry, revocation, reauthentication and provider-required step-up;
- one vault reference can resolve a provider credential bundle;
- account/tenant/geography/currency/permission scope is explicit;
- capability state and source availability remain distinct;
- activation is impossible without successful authorization/eligibility evidence for the selected auth mode;
- connecting an account does not create blanket debit/withdrawal authority; transfer-out capabilities are separately scoped;
- providerless/local-rail activation is possible only when the real external capability, owner authorization, legal/security permissibility and evidence path are established;
- historical provider activation records are immutable;
- provider failure cannot disable unrelated provider instances;
- phase-2 state is updated only by the TL after verified merges.
