# P2-W1-003 — Coverage-Gap Local Rail Program

Owner: Worker 1
Depends on: P2-W1-002, P2-W2-002, P2-W3-002

Implement the Coverage Gap Case workflow and direct-local-provider onboarding path, including local rails that require user-authorized interactive browser/session connectivity rather than a PaySwap-owned provider API credential.

Acceptance:
- every country/method/currency/direction gap can be represented;
- gaps are classified by regulatory, capability, commercial, capacity or reliability cause;
- the workflow selects the narrowest provider/rail integration needed;
- direct local connectors are independently certified;
- local connectors may use DELEGATED_OAUTH, CONNECTED_ACCOUNT, SCOPED_API_CREDENTIAL, INTERACTIVE_BROWSER_SESSION or PROVIDERLESS_RAIL as appropriate;
- browser/session credentials remain inside the secure browser/credential boundary and are never exposed to the agent model;
- account-owner login/MFA establishes authorization; it is not repeated for every transaction unless reauthentication/step-up is required;
- debit/withdrawal scope is explicitly authorized and cannot be inferred from account connection;
- no "global coverage" claim can bypass the matrix;
- blocked/sanctioned/no-route cases are explicit.
