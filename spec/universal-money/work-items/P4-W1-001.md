Implement provider-neutral onchain domain contracts inside the existing Capability/Connector model: chain definitions/instances, asset definitions/observations, protocol definitions/instances, wallet/signer/smart-account capabilities, onchain execution, DEX/bridge/intent capabilities and GenericContractInteractionCapability where appropriate.

Hard constraints:
- no parallel crypto ledger or financial truth model;
- map execution into canonical SettlementInstruction/Attempt/RailOperation/FinalityRecord;
- support non-EVM family semantics without EVM leakage into core contracts;
- catalogue never authorizes;
- external balances are observations;
- no private-key/seed/password/secret fields in agent-facing contracts.

Acceptance: source/callers/tests inspected; canonical package exports; deterministic identity/scope/family/catalogue tests; no duplicate connector vocabulary; exact verification evidence recorded.
