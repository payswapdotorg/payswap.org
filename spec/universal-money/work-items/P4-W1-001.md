# P4-W1-001 — Onchain Domain and Capability Kernel
Owner: worker-1
Dependencies: Phase 3 COMPLETE

Read first: AGENTS.md; docs/SOURCE-OF-TRUTH.md; docs/UNIVERSAL-MONEY-INTERFACE-ARCHITECTURE-2026-10-02.md; ADR-007; this file.

Implement provider-neutral onchain domain contracts inside the existing Capability/Connector model. Add ChainDefinition/Implementation/ConnectedChainInstance, AssetDefinition/Observation, ProtocolDefinition/Implementation/ConnectedProtocolInstance, WalletCapability, SignerCapability, SmartAccountCapability, OnchainExecutionCapability, DEXCapability, BridgeCapability, IntentExecutionCapability and GenericContractInteractionCapability as appropriate to existing package boundaries.

Requirements:
- no parallel crypto ledger or financial truth model;
- onchain execution maps into SettlementInstruction → SettlementAttempt → RailOperation → FinalityRecord;
- support chain-family differences; do not make EVM assumptions part of the core contract;
- external balances are observations;
- provider catalogue never authorizes execution;
- no private-key/seed/password/secret fields in agent-facing contracts;
- generic contract interaction is a controlled escape hatch, never implicit trust.

Acceptance:
- source/callers/tests inspected before implementation;
- contracts compile and are exported from the canonical packages;
- deterministic validation tests cover identity, scope, unsupported families and catalogue-vs-connected distinction;
- no existing connector vocabulary is duplicated;
- exact test commands and commit SHA recorded.
