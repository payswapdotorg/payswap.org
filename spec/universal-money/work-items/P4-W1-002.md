# P4-W1-002 — Wallet/Signer Authorization and Blockchain Security Kernel
Owner: worker-2
Dependencies: Phase 3 COMPLETE

Implement the trusted-surface boundary between PaySwap intent preparation and user-controlled signing.

Add/extend authorization request, signing request, simulation result, expected state/balance diff, scoped delegation, signer adapter and deterministic security-gate contracts.

Minimum constraints evaluated before authorization:
- chain/network;
- asset;
- amount;
- destination;
- spender/approval change;
- expiry;
- route;
- protocol/contract identity.

Supported consequential writes must follow:
prepare → simulate when supported → deterministic policy/security → readable expected-state diff → authorization → immediate pre-broadcast recheck → broadcast.

Requirements:
- no agent direct broadcast/bypass;
- no raw signing secrets anywhere in code paths/artifacts;
- security-agent output cannot downgrade deterministic BLOCK;
- delegation must be attenuated and revocable where the account model permits;
- EIP-712/ERC-1271 support is an adapter concern, not a core-chain assumption.

Acceptance:
- adversarial negative tests prove fail-closed behavior;
- simulation is never treated as authority;
- changed pre-broadcast state invalidates stale authorization;
- exact verification evidence recorded.
