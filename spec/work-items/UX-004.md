Deliverables:

1. **W1 — Create a payment** (converge `pay-journey-surface.tsx` or replace with a new `src/components/workflows/create-payment*.tsx`): segmented One-time | Recurring · currency-prefixed auto-formatting Amount (MoneyInput helpers from `@payswap/design`) · Currency · Counterparty combobox ("Find or add a contact…") · Description · statement/note descriptor · funding-rail section (radio: manual entry / on-file method / hosted link) where dependent options disable WITH reason strings. Per-field inline errors BELOW fields, clear-on-valid, submit blocked until valid (never silent-drop). Confirm = ConfirmationButton restating amount+asset ("Send 25 USDC") with in-button Processing; dual-submit "Send and create another". Success navigates to the payment detail route; failure creates the payment object with `failed` state + human reason (registry id) surfaced for the list/detail.
2. **W2 — Payment link** (new `src/components/workflows/payment-link-builder.tsx` + route under `/app/catalog`-linked `/app/payments/link` or `/app/links` — pick ONE, document it): Select type → Product combobox with inline "Add '\<name\>' as new product" modal (Name/Description/Image/Pricing One-off|Recurring) → payment-page options in tiers (basic: collect name/address/phone, limit payments → advanced: custom fields, promo codes, save details, ToS consent) with every priced option stating its fee inline → **CTA wording selector (Pay · Request · Donate)** → live preview pane (payswap.link URL + "Use your domain" + live estimate "1 × 25 USDC = 25 USDC · Total") → result page (copyable link + Add URL parameters + Embed + Download QR code placeholder-with-honesty + payment-methods list). Honest: unauthenticated/unconfigured renders the honest gate, never a fake link.
3. **W4 — Refund / reversal** (in the payment detail header): modal with amount prefilled (full) + partial-editable field · reason select (human labels from the error-reason registry families) · explicit consequence line ("Returns to customer's wallet on \<rail\>; fees not returned") · confirm → payment state `refunded`/`partially_refunded` (StatusChip renders "Partially refunded" + remaining-amount line when partial) · timeline event in a human sentence · net-balance reversal is an API concern — the UI surfaces the outcome honestly.
4. **Object-detail anatomy** (`src/app/app/payments/[id]/page.tsx` + `src/components/detail/**`): header (display amount + asset · StatusChip · human strapline "Charged to \<name\>" · primary action Refund · overflow) → ActivityTimeline ([Add note] + reverse-chronological human events) → context cards: Execution summary (counterparty · items · total), **Money breakdown** with the MANDATORY cross-rail disclosure sentence ("Customer paid USDC on Base; settled to you in EUR via optimal route") + amount + route/network fees + Net whenever source ≠ settlement asset/rail, Method details (masked "Visa •••• 4242" / "Wallet 0x12…ab90", checks, origin), Risk section (honest test-mode line "Risk insights are only available for live data" — never fabricated scores) → Raw detail card (IDs in metadata typography, copy-on-click with toast, masked by default) → RelatedObjects → receipt/communication history ("No receipts sent" + Send receipt) → events log (human sentence per state change + expandable raw rows). Invalid IDs render the dedicated error page (resource + world + next hop).
5. **Failure-reason surfacing in the payments surface**: the payment list/detail failure surfaces use the certified error-reason registry (`errorReasonById`) for labels + next-action families — no inline free-text error strings in new code.
6. **Tests** (vitest + testing-library): W1 validation matrix (per-field inline errors, clear-on-valid, blocked submit, dependent-disable reasons, dual-submit), ConfirmationButton restatement, W2 tiered options + CTA selector + estimate, W4 partial refund remaining-line, detail anatomy (all seven sections present in order, cross-rail sentence on cross-asset fixture, masked IDs, copy affordance, invalid-id error page), event log human sentences. Fixtures must be clearly TEST-mode (env tokens).
