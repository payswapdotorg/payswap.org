# W2-003 — Capability Ecosystem and Acceptance

Owner: Worker 2
Depends on: W2-002, W1-002

Implement Capability Graph, provider/corridor registry, AcceptanceCapability, ServiceAccessCapability, smart-contract extension representation, PSP capability representation, generalized Connector registry and Connector Capability Packs, extension/package lifecycle and certification integration.

### Connector capability authority

W2-003 owns the canonical connector capability model:
- CapabilityDefinition;
- ProviderImplementation;
- ConnectedCapabilityInstance;
- CapabilityObservation;
- ProviderStateEnvelope;
- hierarchical Connector Capability Packs;
- ExternalFundsLocation / ExternalFundsPositionObservation;
- explicit execution modes: PASS_THROUGH_NATIVE, COMPOSED_PAYSWAP, OPTIMIZED_MULTI_PROVIDER;
- provider-native optimization/recovery as a capability.

Acceptance:
- source availability and capability state remain distinct;
- a provider catalogue claim never authorizes execution for a connected account;
- ConnectedCapabilityInstance records actual account/tenant scope, authorization, geography/currency, eligibility and configuration;
- CapabilityObservation is time/versioned and UNKNOWN when current reachability cannot be established;
- provider state needed for customer actions, reconciliation, support or audit is preserved without lossy canonical mapping;
- capabilities carry proof/economic-accountability metadata;
- smart contracts declare code/address/admin/upgrade/oracle/custody properties and are searchable by the Lab after certification;
- ServiceAccessCapability can describe subscription/entitlement acquisition independently from funding;
- PSP capabilities are provider-neutral;
- connectors for non-PSP systems can expose search/read/write/action/event/health capabilities through the same registry;
- Connector Capability Packs declare auth, schemas, object mappings, source-of-truth policy, rate limits, provenance and evidence;
- large provider packs are hierarchical and independently versioned/certified;
- provider-native optimization/recovery can be represented as a capability without granting Lab authority;
- ExternalFundsPositionObservation is external-state evidence, not PaySwap custody;
- retirement cannot rewrite history;
- merchant acceptance is queryable as a capability.

### Boundary

W2-003 owns capability definitions/catalogue/instance/observation contracts. W3-003 consumes these contracts for execution adapters and must not redefine them.
