# W3-001 — API, Runtime and Experience Boundary Contracts

Owner: Worker 3
Depends on: none
Parallel with: W1-001, W2-001

## Scope
Define contracts for:
- REST/HTTP;
- webhooks;
- trusted approval surfaces;
- runtime adapter;
- MCP;
- A2A;
- AG-UI;
- messaging;
- developer idempotency and authorization.

Create conformance fixtures and contract tests.

## Acceptance
- every mutation is idempotent;
- approval creates explicit authorization artifact;
- UI state derives from protocol state;
- adapters cannot declare finality;
- external versions are explicit.

## Forbidden
No fake payment completion, direct provider SDK in domain code, or chat text as authority.
